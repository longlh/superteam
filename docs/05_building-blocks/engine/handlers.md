# Handlers

A handler does the next step of a work. There is one handler for each type of
event, and the engine loop gives it the events of its type (see
`engineloop.md`).

## Component

Every change of a work goes through the engine loop, as an event: a request of a
client, or a fact such as "a worker has ended". The loop gives the events to the
handlers one at a time, in order, for all the works. So two events never change
the state at the same time, and a step such as the pull request cannot be done
twice by two events at the same time.

| Event               | What its handler does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `work:assign`       | Fetches, finds the workflow on the `base` of the event, the upstream that `assign` checked, and creates the worktree of the work, based on it. Writes the work in it, from the event, with its `base`, and commits it. A work that is already written keeps its own `base`. Creates the task graph in the runtime of the worktree. Runs the tasks that are ready: creates the worktree of each, and publishes `job:run` for its worker.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `worker:ended`      | Records the result of the task: done, with the `summary` and the `dodChecklist` of its worker, or failed with an `error`. A `dodChecklist` whose length is not the number of items of the DOD of the task fails the task. For a done task, it first commits what the worker left in the worktree of the task, pushes the branch of the task, and removes the worktree. Runs the tasks that are ready now: creates the worktree of each, and publishes `job:run` for its worker, or for the task merger first when the task has more than one dependency. When all the tasks are done, publishes `job:run` for the work merger. When a task fails, the work fails: `job:stop` is published for the other jobs of the work, the `error` is written in the work and committed, the branch of the work is pushed, and the worktrees of the work and the branches of its tasks are removed. An event of a task that is already done still runs the tasks that are ready, and the check for the work merger. An event of a failed work fails the work again, so its cleanup is finished. |
| `task-merger:ended` | Writes the `summary` of the task merger in the task, and publishes `job:run` for its worker. A `summary` that is already written is kept, and the job of the worker is published again. When the task merger has failed, the work fails, like a failed worker.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `work-merger:ended` | Writes the `dodChecklist` of the work merger in the work and commits it, opens the pull request on the `base` of the work, with its `summary` in the description, and removes the worktree of the work. When the work merger has failed, the work fails, like a failed worker.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `work:decide`       | When approved, merges the pull request, deletes all the branches of the work, then fetches. When rejected, closes the pull request and deletes the branches of the tasks. The branch of the work is kept.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `work:archive`      | Checks that the work is `FAILED` or `REJECTED`, then deletes the branch of the work, on the remote and on this machine.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `work:fail`         | Enqueued by the engine when an event of a work goes to the DLQ with an error that is not `retryable`, and the worktree of the work is left. Fails the work like a failed task, with `errorCause` `engine` (see ADR 16).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `engine:reconcile`  | Enqueued by `reconcile(jobs)` at the start, so it runs after the events that were left in the queue. Rebuilds from the disk the jobs that the engine waits for, finishes what a stop left undone, and publishes `job:run` again or fails the jobs that were killed (see `reconcile(jobs)` in `engine.md`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |

A handler does not run a job itself. It publishes `job:run` or `job:stop` (see
`pubsub.md`), and the end of a job comes back as an event, through `jobEnded`
(see `engine.md`). A job can be published twice, when a handler is done again,
so a job has an id, and a job that already runs is not run again.

A handler follows the two rules of `engineloop.md`:

- **It does not wait for a long job.** A handler does not run a long job. When a
  job ends, its end is enqueued as a new event, and that event is processed in
  its turn.
- **It can be done again.** An event is given at least once: if the engine stops
  in the middle of a handler, the event is processed again at the next start.
  Before a step the handler checks that the step is not done yet, so a step is
  never done twice, such as the pull request. A step that is already done is
  skipped, but the steps after it are still done, so a retry finishes what a
  throw left undone. A failed work whose worktree is still there is failed
  again, because its cleanup can be done again. When the job of a new task
  cannot be built, the worktree of the task is removed, so a retry starts the
  task.
